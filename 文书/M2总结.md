## 三、服务层详细设计

### 3.1 SecretTypes（数据类型）

定义加密层的三个核心类型：

```swift
// 敏感载荷：实际需要加密的明文数据
struct SecretPayload: Codable, Sendable {
    var password: String
    var secureNote: String?
    var totpSeed: String?
    var customFields: [SecretField]
}

// 加密后的密文容器（存入 Keychain）
struct EncryptedSecret: Codable, Sendable {
    var version: Int          // 加密方案版本号
    var algorithm: String     // "AES-256-GCM"
    var keyID: String         // VaultKey 标识
    var nonce: Data           // AES-GCM nonce
    var ciphertext: Data      // 加密后的载荷
    var tag: Data             // 认证标签
}

// 自定义隐藏字段
struct SecretField: Codable, Hashable, Sendable {
    var name: String
    var value: String
    var isHidden: Bool
}
```

### 3.2 AuthService（本机认证）

```swift
protocol AuthService: Sendable {
    func authenticate(reason: String) async throws
    func canAuthenticate() -> Bool
    func invalidateSession()
    var isSessionValid: Bool { get }
}
```

实现类 `LAAuthService`：

- 基于 `LAContext.evaluatePolicy(.deviceOwnerAuthentication)` 实现
- 支持 Touch ID / Apple Watch / 本机登录密码三种认证方式
- 认证通过后创建 **5 分钟**短期解锁会话
- 使用 `OSAllocatedUnfairLock` 保证 Swift 6 并发安全
- `authenticate()` 先检查 `isSessionValid`，有效期内跳过重复认证
- `invalidateSession()` 清除会话并废弃 `LAContext`

### 3.3 CryptoService（加密服务）

```swift
protocol CryptoService: Sendable {
    func createVaultKey() throws -> SymmetricKey
    func encrypt(_ payload: SecretPayload, itemID: UUID, vaultKey: SymmetricKey) throws -> EncryptedSecret
    func decrypt(_ encrypted: EncryptedSecret, itemID: UUID, vaultKey: SymmetricKey) throws -> SecretPayload
}
```

实现类 `AESCryptoService`：

**密钥层级**：
- `VaultKey`：首次启动生成的 256-bit 随机对称密钥，存入 Keychain（生物识别保护）
- `ItemKey`：通过 `HMAC<SHA256>` 从 `VaultKey + itemID` 派生的每条目独立密钥

**加密流程**：
1. `createVaultKey()` → 生成 `SymmetricKey(size: .bits256)`
2. `encrypt()` → `HMAC<SHA256>` 派生 ItemKey → `AES.GCM.seal()` → 返回 `EncryptedSecret`
3. `decrypt()` → `HMAC<SHA256>` 派生 ItemKey → `AES.GCM.open()` → 返回 `SecretPayload`

**安全特性**：
- 每条目使用独立派生密钥，无法跨条目解密
- AAD（附加认证数据）绑定 `[version] + [itemID]`，防篡改和重放
- 每次加密使用新 nonce（AES.GCM 内置）
- 篡改 ciphertext 或 tag 导致解密失败，抛出 `CryptoError.decryptionFailed`

### 3.4 KeychainStore（Keychain 存储）

```swift
protocol KeychainStore: Sendable {
    func storeVaultKey(_ key: Data) throws
    func loadVaultKey() throws -> Data
    func deleteVaultKey() throws
    func storeSecret(_ data: Data, for secretRef: String) throws
    func loadSecret(for secretRef: String) throws -> Data
    func deleteSecret(for secretRef: String) throws
}
```

实现类 `KeychainStoreImpl`：

- 基于 `Security` 框架的 `kSecClassGenericPassword`
- **VaultKey 存储**：`kSecAttrAccessible = .whenUnlockedThisDeviceOnly` + `SecAccessControl(.biometryCurrentSet)`，强制生物识别才能读取
- **密文存储**：`kSecAttrService = "PwdSafe.Secret"`，`kSecAttrAccount = secretRef`
- 错误类型：`KeychainError.saveFailed` / `.readFailed` / `.deleteFailed` / `.itemNotFound` / `.invalidData`

### 3.5 ClipboardCleaner（剪贴板清理）

- `copyToClipboard(_:clearAfter:)`：写入 `NSPasteboard.general`，默认 30 秒后自动清除
- 使用 `DispatchWorkItem` + `DispatchQueue.main.asyncAfter`（替代非 Sendable 的 Timer）
- 清除前验证剪贴板内容仍与写入时一致，避免误清用户后续复制的其他内容
- 新的 `copyToClipboard` 调用会取消之前的清理任务

## 四、VaultRepository 核心改造

### 4.1 异步化

M1 的同步方法全面升级为 `async throws`：

| 方法 | M1 (同步) | M2 (异步) |
|------|----------|----------|
| `createItem` | `func createItem(_ draft:)` | `func createItem(_ draft:) async throws` |
| `updateItem` | `func updateItem(id:mutation:)` | `func updateItem(id:mutation:) async throws` |
| `permanentlyDelete` | `func permanentlyDelete(ids:)` | `func permanentlyDelete(ids:) async throws` |
| `loadSampleData` | `func loadSampleData()` | `func loadSampleData() async` |

### 4.2 新增方法

| 方法 | 功能 |
|------|------|
| `initializeVault()` | 初始化保险库：加载已有 VaultKey 或创建新 Key 存入 Keychain |
| `revealSecret(id:reason:)` | 认证后从 Keychain 加载密文并解密，返回明文 `SecretPayload` |
| `copyPassword(id:)` | 认证后解密密码并复制到剪贴板（30 秒自动清除） |
| `copyUsername(id:)` | 复制用户名到剪贴板（60 秒自动清除，无需认证） |
| `lock()` / `unlock()` | 锁定/解锁保险库会话 |
| `permanentlyDeleteWithoutAuth(ids:)` | 无需认证的永久删除（用于单条目滑动删除） |

### 4.3 业务事务流程

| 操作 | 流程 |
|------|------|
| **新建** | 生成 secretRef → 加密 SecretPayload → 写 Keychain → 创建 VaultItem |
| **编辑密码** | 加密新 SecretPayload → 更新 Keychain → 更新 VaultItem |
| **查看密码** | `authenticate()` → 读 Keychain → 解密 → 返回明文 |
| **复制密码** | `authenticate()` → 读 Keychain → 解密 → 写剪贴板 + 30s 定时清理 |
| **移到回收站** | `isDeleted = true`，保留 Keychain 密文 |
| **恢复** | `isDeleted = false` |
| **永久删除（需认证）** | `authenticate()` → 删除 Keychain → 删除 VaultItem |
| **永久删除（无认证）** | 删除 Keychain → 删除 VaultItem |

## 六、Swift 6 并发适配要点

| 问题 | 解决方案 |
|------|---------|
| `NSLock.lock()/unlock()` 在 async 上下文不可用 | 替换为 `OSAllocatedUnfairLock`（Swift 6 原生支持） |
| `SymmetricKey.rawRepresentation` 不存在 | 使用 `key.withUnsafeBytes { Data($0) }` |
| `Timer` 不满足 `Sendable` | 替换为 `DispatchWorkItem` + `DispatchQueue.main.asyncAfter` |
| `DispatchWorkItem` 在 `@Sendable` 闭包中捕获报错 | 添加 `@preconcurrency import Dispatch` |
| 测试套件并发执行导致数据竞争 | 添加 `@Suite(.serialized)` 串行化执行 |
| MockAuthService 未实现会话缓存 | 添加 `if isSessionValid { return }` 提前返回 |

## 十、技术要点

1. **双层加密**：VaultKey（Keychain 生物识别保护）→ ItemKey（HMAC-SHA256 派生）→ AES-256-GCM，即使 Keychain 泄露也无法跨条目解密
2. **AAD 绑定**：加密时将 `[version, itemID]` 作为附加认证数据，防止密文被替换到其他条目
3. **OSAllocatedUnfairLock**：Swift 6 推荐的异步安全锁，替代传统 `NSLock`
4. **DispatchWorkItem**：替代非 Sendable 的 `Timer`，实现剪贴板定时清理
5. **Mock 服务注入**：`VaultRepository` 通过构造函数注入 `AuthService` / `CryptoService` / `KeychainStore`，测试时替换为 Mock 实现
6. **@Suite(.serialized)**：防止测试套件内并发执行导致的数据竞争
