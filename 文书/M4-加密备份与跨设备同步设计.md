# M4 阶段：加密备份与跨设备同步设计

生成日期：2026-05-14
定位：基于 M3 本地完成的加密备份体系升级，解决 VaultKey 跨设备分发与备份迁移问题

---

## 一、要解决的问题

### 当前架构

```
VaultKey ─(AES-256-GCM)─→ EncryptedSecret ─→ Keychain (ThisDeviceOnly)
                                                         ↓
                                             导出 .pwd ─→ 备份文件含 EncryptedSecret 密文
                                                              ↓
                                              导入新设备 ─→ ❌ 没有 VaultKey，无法解密
```

**核心缺陷**：VaultKey 是设备绑定的随机密钥，`pwd` 备份文件导出后，在新设备上无法解密。CloudKit 同步同理，密文过去了但密钥过不去。

### M4 目标

1. **VaultKey 跨设备共享**：多台 Mac 使用同一个 VaultKey，无需手动导出/恢复
2. **备份可迁移**：`.pwd` 文件在任意设备（含非 Apple 平台）上可解密恢复
3. **恢复码机制**：离线/灾难恢复场景下，通过 12 词助记词恢复保险库
4. **不引入主密码**：日常解锁仍用 Touch ID / Apple Watch / 本机密码，不改用户习惯

---

## 二、核心设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| VaultKey 分发 | iCloud Keychain 同步 | Apple PKI 现成可用，零代码量，安全性等价于手动 PKI |
| VaultKey 生成方式 | 保持随机 `SymmetricKey(size: .bits256)` | 不引入主密码派生，保持现有解锁流程不变 |
| 恢复码 | BIP39 12 词 → P-256 key pair → ECIES 包裹 VaultKey | 私钥离线持有，跨平台可用 |
| 云端权威判定 | 远程强同步 + VaultManifest CKRecord | 远程状态始终优先，避免多 VaultKey 冲突 |
| 冲突处理 | 自动重加密（远程 VaultKey 为准） | 用户无感知，数据不丢失 |

## 三、VaultKey 跨设备同步方案

### 3.1 存储属性变化

```swift
// 旧 (KeychainStoreImpl.swift)
kSecAttrAccessible: kSecAttrAccessibleWhenUnlockedThisDeviceOnly
// + SecAccessControl(.userPresence)

// 新
kSecAttrAccessible: kSecAttrAccessibleWhenUnlocked  // 去掉 ThisDeviceOnly
kSecAttrSynchronizable: true                         // 打开 iCloud KC 同步
// 去掉 SecAccessControl(.userPresence) — App 层 AuthService 已做生物认证
```

### 3.2 VaultManifest（云端权威记录）

在 CloudKit 私有数据库中维护一条 `VaultManifest` 记录，作为「保险库是否存在」的权威判断标志。

```swift
// 新增: Models/VaultManifest.swift
struct VaultManifest: Codable, Sendable {
    var vaultID: UUID          // 保险库唯一 ID
    var activeKeyID: String    // 当前 VaultKey 的 SHA256 哈希
    var recoveryPubKey: Data   // 恢复码公钥 (P-256, ANSI X9.63)
    var createdAt: Date
    var updatedAt: Date
}
```

**作用**：
- 新设备启动时先查 Manifest → 知道是否有远程保险库
- Manifest 存在 + VaultKey 尚未从 iCloud KC 同步 → 等待同步
- Manifest 不存在 → 真正的首次创建，写 Manifest

### 3.3 CloudKit 配置

```
Container:  iCloud.com.pwdsafe
Database:   private
Zone:       CKRecordZone.default()
RecordType: "VaultManifest"
Record:     一条（单例，用固定 recordName: "vault-manifest"）
```

## 四、恢复码方案

### 4.1 设计

```
首次创建保险库时:
  1. CryptoKit 生成 P-256 key pair
  2. 私钥 → BIP39 12 词助记词（显示给用户，仅此一次）
  3. 公钥 → 写入 VaultManifest + 备份文件
  4. VaultKey ──ECIES(公钥)──→ RecoveryBlob（写入 .pwd 备份文件）
```

### 4.2 BIP39 词表

使用标准 BIP39 英文词表（2048 词），从 32 字节种子取前 128 bits 映射为 12 词。实现参考 — 直接在项目内嵌入词表文件或 hardcode。

### 4.3 备份文件结构

```swift
struct BackupRecord: Codable, Sendable {
    var version: Int                    // 升级为 2
    var vaultKeyID: String              // 新增: VaultKey 指纹
    var recoveryBlob: RecoveryBlob      // 新增: 恢复码加密的 VaultKey
    var createdAt: Date
    var appVersion: String
    var items: [BackupItem]             // 不变（EncryptedSecret 仍是 VaultKey 加密）
    var groups: [BackupGroup]
    var tags: [BackupTag]
}

struct RecoveryBlob: Codable, Sendable {
    var pubKeyX: Data                   // P-256 公钥 X 分量
    var pubKeyY: Data                   // P-256 公钥 Y 分量
    var nonce: Data                     // ECIES 临时公钥
    var ciphertext: Data                // ECIES 加密的 VaultKey
    var tag: Data                       // AES-GCM tag
    var keyID: String                   // 恢复码公钥指纹（用于定位）
}
```

### 4.4 恢复流程（非 Apple / 全新设备）

```
1. 安装 PwdSafe
2. 选择「从备份恢复」→ 导入 .pwd 文件
3. 输入 12 词恢复码 → BIP39 seed → P-256 私钥
4. 用私钥 ECIES 解密 recoveryBlob → 得到 VaultKey
5. VaultKey 解密 EncryptedSecret → 恢复密码
6. VaultKey 写入 iCloud Keychain（从此以后 iCloud 设备自动同步）
```

## 五、同步策略（3 态决策表）

| | Local 不存在 | Local 相同 | Local 不同 |
|---|---|---|---|
| **Remote 不存在** | **创建全新保险库**<br>• 生成 VaultKey<br>• 生成恢复码 key pair<br>• 写入 Manifest | 无动作<br>(等待联网上传) | 保持 local<br>(等待联网后走 →) |
| **Remote 相同** | **加载 remote**<br>• 从 iCloud KC 加载 VaultKey<br>• 正常新设备加入 | ✅ 无动作 | 🔄 方案 2 |
| **Remote 不同** | — | — | 🔄 **方案 2：自动重加密** |

### 方案 2：本地解密 → 远程重加密（自动迁移）

```
触发条件: 本地 VaultKey ≠ 远程 VaultKey (keyID 对比)
处理流程:
  1. 遍历本地所有 EncryptedSecret
  2. 用旧 VaultKey_B 解密 → SecretPayload
  3. 用远程 VaultKey_A 重新加密 → EncryptedSecret'
  4. 写入 Keychain，更新 secretRef 对应的 EncryptedSecret
  5. 旧 VaultKey_B 丢弃
  6. 恢复码公钥也切换为远程 Manifest 中的公钥
  7. 如本地之前生成过 12 词，弹窗提示作废
```

**用户提示（仅当本地有离线新建的恢复码时弹出）**：

```
检测到 iCloud 已有保险库（创建于 2026-05-10）
本机刚创建的临时保险库已被同步覆盖

⚠️ 请忽略本机刚才显示的 12 词恢复码
  保险库的恢复码以最早创建时生成的为准
  如需重新查看恢复码，请在原创建设备上导出
```

## 六、初始化完整流程

```
PwdSafeApp 启动
    │
    ▼
AuthService 解锁
    │
    ▼
initializeVault()
    │
    ├── 1. 读取本地 Keychain VaultKey (kSecAttrSynchronizable: true)
    │      │
    │      ├── 存在 → vaultKey = 加载的值 → 跳至步骤 5 (VaultKey 已就绪)
    │      │
    │      └── 不存在 →
    │             │
    │             2. 等待 iCloud KC 同步（最多 5 秒）
    │                │
    │                ├── 同步到 VaultKey → vaultKey = 同步来的值 → 跳至步骤 5
    │                │
    │                └── 仍未同步到 →
    │                       │
    │                       3. 查询 CloudKit VaultManifest
    │                          │
    │                          ├── Manifest 存在 →
    │                          │     等待 iCloud KC 同步完成（延长等待 + 用 Manifest 的 keyID 校验）
    │                          │     同步到 → 跳至步骤 5
    │                          │
    │                          └── Manifest 不存在 →
    │                                 │
    │                                 4. 首次创建保险库
    │                                    a. 生成 VaultKey ← SymmetricKey(size: .bits256)
    │                                    b. 生成 P-256 key pair
    │                                    c. 私钥 → BIP39 12 词 → 展示给用户（仅此一次）
    │                                    d. 写入 VaultManifest 到 CloudKit
    │                                    e. VaultKey + 恢复码公钥 存入 iCloud KC
    │                                    ▼
    └── 5. VaultKey 就绪
           │
           ├── 比对 keyID (本地 vs Manifest)：
           │      ├── 相同 → 直接加载本地数据
           │      └── 不同 → 执行方案 2 自动重加密（见第五节）
           │
           └── loadMetadata() → 加载/加载示例数据
```

## 九、测试场景

### 9.1 基本同步

- iCloud 已登录 → 创建保险库 → VaultManifest 写入成功
- 新 Mac 登录同一 iCloud → 启动 PwdSafe → iCloud KC 同步 VaultKey → 直接加载
- 断网时创建 → 本地可用 → 联网后自动同步

### 9.2 离线-在线冲突（方案 2）

- Mac B 离线 → 生成 VaultKey_B → 创建 2 条密码
- Mac B 联网 → Manifest 已有 Mac A 的 VaultKey_A
- 自动触发重加密 → 2 条密码用 VaultKey_A 重加密
- 本地恢复码弹窗提示作废
- 验证：用 VaultKey_A 解密所有条目成功

### 9.3 备份/恢复

- 导出 .pwd (v2) → 文件含 recoveryBlob
- 另一台 Mac 上导入 → 输入 12 词 → 解密成功 → 数据恢复
- recoveryBlob 中的 keyID 正确匹配

### 9.4 恢复码生命周期

- 首次创建 → 展示 12 词 → 用户确认已保存
- 12 词不存 Keychain、不存 CloudKit、不存备份文件
- 恢复码公钥正确写入 Manifest
- recoveryBlob 能被对应私钥正确解密

### 9.5 加密备份格式兼容

- M3 导出的 v1 .pwd 文件 → 新版本能识别并提示格式升级
- v2 .pwd 文件 → 新版本正常导入
- 旧设备（仅 VaultKey 本地）导出 → 新设备恢复 → 需输入 12 词
